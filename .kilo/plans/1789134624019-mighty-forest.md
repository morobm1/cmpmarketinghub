# Competitor Cards — Implementation Plan

## A. Existing Architecture Findings

**File:** `competitor_cards.html` (3811 lines) — single-file IIFE app (starts line 559), no framework, no build step, no router. Backed by Netlify Functions + MongoDB (`netlify/functions/competitor-cards.js`, schemaless `$set` updates on PUT — additive fields are free).

- **Data model:** One unified shape `createEmptyCard(cardType)` (line 684) for both "Our Property" (`cardType:'subject'`) and competitors (`cardType:'competitor'`). Only **one** subject card per property (`subjectCard`, singular global, not an array). Key fields: `heroImage` (single string, no gallery), `floorplanDetails: [{name, bedsBaths, sqft, rate}]` (all strings, **no id**, referenced by array index), `topAmenities` (free-text string), fees/specials/strategy fields.
- **Persistence:** `apiGet/apiCreate/apiUpdate/apiDelete` (lines 715-734) hit `/api/competitor-cards`, scoped by `property` (tenant). Global mutable state: `cards[]`, `subjectCard`, `currentCard`, `currentUser`, `currentProperty` (lines 645-658). `loadCards()` (2211) → `renderGallery()`.
- **Auth/Admin:** Cookie-based JWT via `/api/me`. Admin = `currentUser.role === 'admin'` (only real check, used at line ~3767 to show/hide `#adminPageBtn`). `getAccessible()` (705) gives admins all properties.
- **Edit/save:** Single shared editor — `renderEditor()` (1441), `buildForm()` (1687), `renderFPRows()` (1850) for floorplans. Save via `handleSaveDraft()`(2155)/`handleSaveComplete()`(2177) → `updateCardInState()`(2144).
- **No modal system** — every "screen" is a full swap of `els.mainContent.innerHTML` driven by `currentView`. Toasts: `showToast()` (678).
- **No "Analyst" tab exists today** — `analystName` is just a per-card metadata field. Item 5 requires **adding** an Analyst section, not editing one.
- **Rate Comparison:** `buildRateCompareHTML()` (3079) + `extractBedroomType()` (3054, regex-based bucketing — the only cross-property floorplan matcher) + `parseRateNum()` (3127).
- **Amenity Cart:** `buildAmenityCartHTML()` (3232) — hardcoded `AMENITY_GROUPS` keyword buckets; `amenityOverrides` keyed by **array index**, never persisted.
- **Comparison Matrix (report):** `buildComparisonTableHTML()` (2996) — CSS grid of vertical cards (matches the PDF's "3 vertical cards" complaint exactly).
- **Report Builder/PDF:** `renderReportBuilder()` wizard (2247), `renderReportPreview()` (2556) builds one long HTML deck (reusing `renderPreview()` for property cards — tight coupling), then **`window.print()`** — no jsPDF/html2canvas, no `@page` rule, no orientation control (confirmed in CSS lines 340-400). This is exactly why the reference PDF is portrait, has orphaned headers (page 13), and stacked vertical cards.
- **Excel:** SheetJS `xlsx-0.20.1` already loaded (line 13), already used both ways: `handleImportFile()`(1091)/`downloadCompetitorCardTemplate()`(1144) for competitor import, `exportToExcel()`(2702) for export. **Import only ever creates `cardType:'competitor'`** — no subject-card import path exists yet.
- **College House workbook (inspected directly):** 5 sheets confirmed — `Overview` (1 row of market KPIs: Purpose Built Beds/Properties, Avg Rate, Avg Rate/SF, Occupancy, Pre-lease, Planned/Under Construction/Lease-Up Beds, Estimated Excess, plus **bedroom-level** rate/occupancy/bed-count columns for Studio–6BR), `Fundamentals` (1 row, cap rate/IRR/growth metrics), `Universities` (multi-year enrollment history), `Properties` (~750 rows — one row per floorplan across ~150+ Gainesville properties, columns: Property, Floor Plan, Bedrooms, Bathrooms, Floor Plan Total Beds, Square Feet, Occupancy, Rental Rate, Effective Rate, concessions), `Sales Comps` (transaction history: buyer/seller/price/date). This is a full third-party market dataset, not competitor-shaped data — confirms it must NOT be auto-converted into competitor cards.
- **Reference PDF (inspected directly):** Confirms every stated failure — portrait Letter, blank trailing space on cover/property pages, a page containing only the "COMPARISON MATRIX" header with content starting on the next page (orphaned header), 3 vertical property cards for the Comparison Matrix, Rate Comparison/Amenity Cart tables rendered as shrunk screenshots.

## B. Reuse As-Is

- `createEmptyCard`, `apiGet/apiCreate/apiUpdate/apiDelete`, `updateCardInState`, `loadCards`, `getAccessible`
- `showToast`, the full-page-view-swap convention (`currentView` + `render*()` into `els.mainContent`)
- `buildForm`/`renderFPRows` pattern for new editable tables (Future Rates editor will mirror this)
- `parseAmenities`, `extractBedroomType`, `parseRateNum` (extend, don't fork again — see C)
- SheetJS `XLSX` global (already loaded) for all new import/export features
- `handleEditCard`/`renderEditor` extension points (add new buttons into the existing toolbar rather than new screens where possible)
- Admin check pattern: `currentUser.role === 'admin'`
- Netlify PUT's `$set`-only semantics — confirms adding new top-level fields (`floorplanDetails[].id`, `futureRates`, `collegeHouseData`) requires zero backend changes as long as the client only ever sends fields it intends to change (must audit `apiUpdate` calls to avoid accidentally clobbering fields not loaded into `currentCard`).

## C. Extend (not replace)

- **`floorplanDetails`**: add non-breaking `id` (generate on first touch if missing) so Future Rates / Rate Comparison can reference floorplans stably instead of by index/regex. Keep `extractBedroomType` as fallback matcher for legacy records without ids.
- **Card schema**: add `futureRates: { [floorplanId or normalizedKey]: { rate, updatedAt } }` and `collegeHouseData: { raw: {...sheets}, normalized: {...KPIs}, importedAt }` on the **subject card only**.
- **`buildRateCompareHTML`**: add a `rateSource` param (`'current'|'future'|'currentVsFuture'`) and SQ FT / Rate-per-SQFT columns with divide-by-zero/NaN/Infinity guards.
- **`buildAmenityCartHTML`**: fix pagination/overflow for export only; keep vertical-amenity/horizontal-property structure; switch `amenityOverrides` key from array index to `card.id` while here (fixes an existing correctness bug, low risk, high value).
- **`buildComparisonTableHTML`**: replace vertical-card grid with horizontal metric-rows table for the **report only** (leave `renderComparison()`, the interactive in-app comparison view, untouched).
- **`renderReportPreview` / print pipeline**: replace `window.print()`-only pipeline with a dedicated jsPDF+html2canvas paginated landscape pipeline (see D) while keeping `renderReportBuilder()` wizard steps 1-2 as-is; only step 3 (preview/generate) and the underlying builders change.
- **`exportToExcel`**: keep as the competitor-only quick export; add new, separate, more structured `exportPropertyToExcel(card)`/`exportCompetitorToExcel(card)` + `downloadCleanTemplate(cardType)` + `importExcelIntoCard(file, currentCard)` helpers that reuse a shared `sheetFromCard()`/`applyRowsToCard()` core instead of duplicating `exportToExcel`'s ad-hoc aoa building.
- **Admin gating**: extend the existing `me.role==='admin'` check to also gate a new nav entry/button for Bulk Image Update (no new auth mechanism).

## D. Implementation Order

1. **Data model additions** (additive only): floorplan `id` backfill helper, `futureRates`, `collegeHouseData` fields; central `getFloorplanId(fp)`/`ensureFloorplanIds(card)` helper used everywhere floorplans are read.
2. **Admin Bulk Image Update** (self-contained, lowest risk, validates admin-gating pattern early): new view, loop `apiGet()` across admin's accessible properties, diff-only PUT via `apiUpdate`.
3. **Our Property Excel Import/Export** (Property Details/Floorplans/Amenities/Fees/Utilities/Parking/Specials sheets) — build shared `sheetFromCard()`/`applyRowsToCard()` helpers; blank-cell-preserves-existing-value merge logic.
4. **Competitor Excel Import/Export** using the same shared helpers (item 3 must land first).
5. **Future/Held Rates** (data entry UI keyed off `floorplanDetails`/floorplan `id`; save into `card.futureRates`).
6. **Analyst > Held Future Rates** view (reuses item 5's data + adds Status derivation).
7. **Rate Comparison rate-source selector + Current vs Future + SQ FT/Rate-per-SQFT** (extends `buildRateCompareHTML`; depends on 5).
8. **College House Market Overview** — importer built directly from the confirmed sheet layout (Overview/Fundamentals/Universities/Properties/Sales Comps), stores raw + normalized on subject card, dedicated KPI view + Replace/Upload.
9. **Report Builder rebuild**: new report-only rendering module (config → data-prep → render → PDF via jsPDF + html2canvas), landscape-letter (11x8.5) export container, decoupled from `renderPreview()`. Add jsPDF + html2canvas via CDN (pin exact versions, e.g. `jspdf@2.x`, `html2canvas@1.4.x`). Build a hidden, off-screen export container sized exactly to landscape Letter so rendering never depends on viewport/scroll/current horizontal scroll position. Render each report section (cover, property snapshots, Comparison Matrix, Rate Comparison, Amenity Cart, College House Overview) into separate export-container pages, `html2canvas` each page individually (not one giant capture) to control page breaks explicitly, then assemble via `jsPDF.addImage` per page with `addPage()` between — this avoids the "avoid breaking mid-table" problem by deciding page boundaries in JS/layout rather than relying on CSS `break-inside`. Remove/replace the `window.print()` code path rather than leaving it dangling. This is the largest single item in the plan.
10. **Report snapshots, horizontal Comparison Matrix, Rate Comparison report, Amenity Cart pagination, College House report section** — built on top of item 9's new rendering module.
11. **Regression pass**: manual smoke test of every item in section G/17 of the request (gallery, new/edit competitor, new/edit subject, duplicate, archive, compare, rate compare, amenity cart, report builder full flow, Excel import/export both card types, admin bulk image tool, presentation/print mode).

## E. Highest Regression Risks

1. **`renderReportPreview` reuses `renderPreview()`** to build property cards — redesigning the report will require detaching this reuse; must verify the live editor preview is unaffected.
2. **`amenityOverrides` keyed by array index** — any change to card set/order (which the new College House section, new report sections, or reordering could trigger) risks silently applying overrides to the wrong property; fix opportunistically in step 10.
3. **Floorplan matching is done 3 different, independent ways** (`extractBedroomType`, `exportToExcel`'s inline regex, `AMENITY_GROUPS` substring logic) — introducing floorplan `id` must not break the two that don't use `extractBedroomType`.
4. **`window.print()` timing hack removal** — replacing with a real jsPDF/html2canvas/landscape pipeline is a substantial rewrite of a fragile-but-working path; must test on a large report (5+ competitors) before/after, and ensure html2canvas correctly captures content that would normally require horizontal scrolling (per-page render at fixed export-container width avoids this).
5. **Bulk image tool touching cards across multiple properties** — must not accidentally use the single-property `apiGet()`/`currentProperty` global state; must not leave `currentProperty`/`cards`/`subjectCard` mutated after the tool closes.
6. **Backward compatibility** — existing cards lack `floorplanDetails[].id`, `futureRates`, `collegeHouseData`; every new function must tolerate `undefined`/missing shapes (no destructuring without defaults).

## F. Do NOT Touch

- `renderComparison()` (1544) — the interactive in-app Comparison view (distinct from the report's Comparison Matrix; user only asked to change the export version).
- `apiGet/apiCreate/apiUpdate/apiDelete` request/response contracts and `netlify/functions/competitor-cards.js` (no backend schema changes needed — Mongo is schemaless and PUT already does partial `$set`).
- `checkPropertyAccess`/`getAccessible` admin logic — reuse, don't reimplement.
- Existing competitor Excel import (`handleImportFile`, `downloadCompetitorCardTemplate`, `IMPORT_FLOORPLAN_SLOTS` flow) and `exportToExcel()` — leave functional as-is; add new functions alongside rather than modifying, since existing import wizard is production-tested.
- `standard-nav.js` integration points (`#sidebarNav`, `#navToggle`, `.main-content` toggling in presentation mode).

## G. Libraries

- **SheetJS `xlsx-0.20.1`** (full build, already loaded line 13) — covers all Excel import/export needs (items 2, 3, 8).
- **New dependencies to add:** jsPDF (`jspdf@2.x`) + html2canvas (`html2canvas@1.4.x`) via CDN, pinned to explicit versions during Code mode, for the Report Builder rebuild (item 9). Decision confirmed with user: use a real PDF library rather than staying with print-CSS/`window.print()`, for precise landscape-letter pagination control.
- Google Fonts / Typekit — unrelated, no change needed.
