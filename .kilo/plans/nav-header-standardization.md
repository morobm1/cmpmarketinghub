# Global Navigation + Header Standardization — Implementation Plan

## A. Existing architecture findings (verified by direct inspection)

- **`standard-nav.js`** is already the ONE shared/global nav script, included via `<script src="standard-nav.js"></script>` on 14 pages (mmp_calendar_app.html, mmp_calendar_app_v2.html not included, competitor_cards.html, mplr.html, creative_studio.html, creative_library.html, custom_tools.html, leasing_staff_list.html, marketing_contacts.html, marketing_plans.html, mmp_monthly_plan.html, promo_order_tracker.html, sop_library.html, velocity_tracker.html, uniform_shop.html). It already: injects nav CSS, injects the vertical sidebar HTML from a hardcoded `fullNavStructure` object, wraps page content in `.main-content`, persists collapse state in `localStorage` (`mmp_nav_collapsed`), handles mobile drawer, and already has bespoke role-based structure-swapping for `maintenance` and `reslife-*` roles (redirect-away logic). **This is the correct extension point — not a new system.**
- **Roles** (from `mmp_admin.html`'s `ROLE_META`, the actual canonical list): `user`, `admin`, `maintenance`, `reslife-ra`, `reslife-rec`, `reslife-admin`. Auth is JWT/cookie via `_auth.js` (`verifyReqAuth`), unchanged.
- **`mmp_admin.html`** already has a `.modal-overlay/.modal/.modal-header/.modal-body/.modal-footer/.modal-close` pattern (reuse for Navigation Manager) and a `.tab-btn`/`.tabs` internal section-switcher (Users/Properties/Uniform Catalog) — unrelated to cross-app nav, left untouched. It also has its OWN redundant cross-app top nav row (`<nav class="nav-bar">` with `.nav-tab` links to Marketing Calendar/Plans/etc.) — a genuine duplicate of what `standard-nav.js` provides everywhere else. Its `<header>` markup/CSS is already byte-for-byte identical to the canonical reference (no bug there). Its whole page body is a single `<main id="appContainer" class="container hidden">` — easy to fold into `.main-content`.
- **Reslife Hub** (`reslife_hub.html`) has its own separate, purpose-built `.rl-sidebar` (different brand/theme, per-property, already reviewed/extended in prior sessions) — **not** built on `standard-nav.js` and out of scope to merge (different product area, explicitly not to be redesigned). Only needs one new admin-only link added to its existing sidebar list.
- **Existing per-user tool links** (`custom-tools.js` + `custom_tools.html`) are a *different*, already-working feature (personal shortcuts saved per-username) — not to be confused with or merged into the new global admin-managed nav config; kept fully separate.
- **Root cause of every reported header/nav bug, confirmed by direct inspection:**
  - `competitor_cards.html`: local `header{}` rule has a stray `padding-left:256px` (a hard-coded sidebar-avoidance offset that isn't needed — the canonical pages don't pad the header at all because the sidebar sits *below* the header, not beside it).
  - `creative_studio.html`: identical bug (`padding:0 24px 0 256px` on `.cmp-header`), plus it uses `position:fixed` + `!important` height math instead of the canonical `position:sticky` pattern (kept intentionally, see D below, because the embedded email-shop bundle relies on `.main-content` being an exact non-scrolling viewport box).
  - `mplr.html`: has **no static `<header>` at all** — its header is rendered later, client-side, by the compiled React bundle (`mplr-app/dist/assets/mplr.js`, source `App.tsx`). Since `standard-nav.js` looks for `document.querySelector('header')` at script-run time and finds nothing, it falls back to inserting the sidebar as the first `<body>` child, and `.main-content` ends up wrapping `#mplr-root` — so once React mounts, its own sticky header renders *inside* `.main-content` (pushed right by the sidebar margin, not full-width like every other page). Editing/rebuilding the Vite bundle is out of scope/high-risk; fixed at the shell level instead (see D).
  - `velocity_tracker.html`: header CSS uses `z-index:20`, while the injected sidebar uses `z-index:30` and a **hardcoded** `top:60px`. If the header ever renders taller than 60px (its `flex-wrap:wrap` allows this on medium widths), the higher-z-index sidebar visually covers the bottom of the header. Root cause is the hardcoded 60px assumption in `standard-nav.js` itself, not a velocity_tracker-only bug — fixing it centrally (dynamic header height) fixes this page and prevents recurrence everywhere.

## B. Reuse (do not rebuild)

- `standard-nav.js`'s existing CSS-injection, HTML-injection, collapse-persistence, mobile-drawer, and role-redirect logic for `maintenance`/`reslife-*`.
- `mmp_admin.html`'s existing `.modal-overlay/.modal/...` component and `.tab-btn` styling for the Navigation Manager's own internal UI.
- `_auth.js` / `verifyReqAuth` — no new auth system.
- `custom-tools.js` pattern (simple Mongo CRUD keyed by a collection) as the template for the new `nav-config.js` function.
- Existing CSS variables/design tokens (`--brand-primary`, `--brand-accent`, `--border`, etc.) already shared across every page's `:root`.

## C. New/centralized configuration

- **New collection `navConfig`** (one document per nav item): `{ id, name, icon, destinationType: 'project'|'custom'|'external', link, section: 'main'|'tools'|'resources', order, enabled, roles: string[] }`. Empty `roles` = visible to everyone. Auto-seeded on first read from the *exact current* hardcoded list in `standard-nav.js`, so migration is lossless.
- **New `netlify/functions/nav-config.js`**: GET (any authenticated user, auto-seeds if empty) / POST, PUT (including a `{action:'reorder'}` bulk path), DELETE (Admin-only, `role==='admin'`).
- `standard-nav.js` fetches this once per page load, transforms it into the same `{main:[],tools:[],resources:[]}` shape its existing render code already expects (minimal change to rendering, only the data source changes), filters by the current user's role, and falls back to the original hardcoded array if the fetch fails (zero risk of a broken nav).
- Icons: switch from inline hand-drawn SVGs to **Bootstrap Icons** (free, single `<link>` CDN, `<i class="bi bi-xxx">` usage, no build step, no API key) — chosen because it's the lightest free option that needs zero JS tooling and has a huge searchable set for the icon picker. Existing hardcoded nav items keep working (icon field defaults are pre-mapped to sensible `bi-*` classes in the seed data); custom/admin-added items pick from the same set.

## D. Targeted fixes (in order)

1. **`netlify/functions/nav-config.js`** — new file as described above.
2. **`standard-nav.js`** — extend, don't replace:
   - Load Bootstrap Icons CDN `<link>` if not already present.
   - Fetch `/api/nav-config`, map to grouped structure + role filter; keep hardcoded array as fallback only.
   - Add one extra, code-level (non-editable-by-admin-UI) item: "Reslife Hub" → `reslife_hub.html`, shown only when `me.role === 'admin'`.
   - Replace the hardcoded `top:60px` / `height:calc(100vh - 60px)` / `margin-left` companion math with a `--app-header-h` CSS custom property set from the real header's measured height (`ResizeObserver` + initial measurement, fallback `60px`), used by `.sidebar-nav`/`.main-content`. This is the general fix for the velocity_tracker/mplr class of bug.
   - Move the canonical header CSS (`header`, `.brand`, `.brand .logo-img`, `.brand .title`, `.header-controls`, `.header-btn`, `.company-name`) into the same injected `<style>` block — the single shared header system.
3. **`competitor_cards.html`** — remove the local duplicate `header/.brand/...` block (incl. the `256px` bug); shared CSS now supplies it.
4. **`creative_studio.html`** — fix `padding:0 24px 0 256px` → `padding:0 24px`; remove the now-duplicate `.brand`/`.logo-img`/`.title` rules; keep the page-specific `.cmp-header{position:fixed;height:60px;overflow:hidden}` sizing (documented exception — required by the embedded, non-scrolling email-shop bundle; functionally equivalent to `sticky` here since `body{overflow:hidden}` already prevents page scroll, so no behavior change, only the alignment bug is fixed).
5. **`mplr.html`** — add a static canonical `<header>` (logo + "Marketing Hub") to the shell, outside `#mplr-root`, so `standard-nav.js` anchors correctly; the React app's own internal bar (property switch/admin/logout) continues to render unchanged, now correctly appearing as a secondary bar below the standardized header instead of mis-nested beside the sidebar. (Documented trade-off: not editing/rebuilding the Vite bundle — safer, avoids build-tooling risk, zero functional change to MPLR itself.)
6. **`mmp_admin.html`**:
   - Remove the redundant `<nav class="nav-bar">…</nav>` cross-app row + its CSS (consolidating a duplicate nav implementation into the one shared system).
   - Add `main-content` class to the existing `<main id="appContainer">` and add `<script src="standard-nav.js"></script>` before `</body>` — the page now gets the same sidebar as everywhere else, including the new Admin→Reslife Hub link, automatically.
   - Add a **"Navigation Manager"** tool card that opens a modal (existing `.modal-overlay/.modal` pattern) listing all nav items grouped by section, with: enable/disable toggle, edit (name/icon/destination type + value/section/roles), delete (confirm), add-new, and reordering via simple Up/Down buttons per row (no drag-and-drop dependency — explicitly allowed as the lighter alternative). Destination-type selector drives the link field: Project Page (dropdown of the actual known Marketing Hub `.html` pages, statically enumerated from the same list `standard-nav.js` already knows about — file-system discovery isn't available client-side in this static-hosting/Netlify-Functions architecture, so a maintained list is the correct, honest choice rather than a fake "auto-discovery"), Custom/Internal Path (free text), External URL (free text, validated with `new URL()`, forced `target="_blank"` when rendered). Already-used project pages are visibly flagged "Already Used" in the dropdown (except the item currently being edited).
7. **`reslife_hub.html`** — add one admin-only sidebar entry ("Marketing Hub" → `index.html`/Marketing Hub landing) inside the existing `.rl-sidebar` render, gated by the already-computed `me.role === 'admin'` flag used elsewhere in that file. No other Reslife Hub changes.

## E. Explicitly out of scope / preserved as-is

- Reslife Hub's own sidebar visual system (not migrated to `standard-nav.js`).
- `custom-tools.js`/`custom_tools.html` (untouched, different feature).
- The MPLR/Creative Studio compiled Vite bundles (not rebuilt).
- Per-page duplicate header CSS on the ~9 pages *not* otherwise touched (mmp_calendar_app.html, velocity_tracker.html, marketing_plans.html, mmp_monthly_plan.html, promo_order_tracker.html, uniform_shop.html, creative_library.html, marketing_contacts.html, leasing_staff_list.html, sop_library.html) — values are byte-identical to the new shared rules, so there is no visual conflict or regression risk in leaving them; only the 3 explicitly-broken files plus the one being deeply edited (mmp_admin.html) get their local copies removed. This bounds blast radius while the shared CSS still makes every page consistent in practice.
- No drag-and-drop library, no icon-image uploads, no second auth system, no framework introduced.

## F. Self-review checklist to run after implementation

Nav (expanded/collapsed/active/internal/external/admin-only/role-filtered/order/enable-disable), Header (logo/title position, height consistency, responsive), Navigation Manager (add/edit/delete/reorder/icon picker/page selector/dup-prevention/roles), regression check on Marketing Calendar, Velocity Tracker, Competitor Cards, MPLR, Creative Studio, Reslife Hub, Admin tools, login/roles — plus duplicate-ID/duplicate-function/syntax checks via `node --check` on every edited inline `<script>`, matching the verification approach used in prior sessions on this project.
