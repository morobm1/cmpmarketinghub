SOP Library – How It Works & How to Add SOPs

Administration All Staff

System: Marketing Hub Web Application  |  Location: sop_library.html

Section 1 – Purpose

This Standard Operating Procedure documents how the SOP Library works within the Capstone Management Partners Marketing Hub. It covers the system architecture, how SOPs are organized and displayed, and provides step-by-step instructions for creating, editing, and managing SOPs.

The SOP Library is a web-based document management system that stores Standard Operating Procedures in a MongoDB database and presents them through a clean, searchable interface.

Section 2 – When to Use This Process

Refer to this document when you need to:

  • Create a new SOP for a company-wide or site-specific procedure
  • Edit an existing SOP to update steps, add training videos, or correct information
  • Understand how SOPs are organized (types, categories, visibility)
  • Share an SOP with a team member via a direct link
  • Export an SOP to Word or PDF format
  • Troubleshoot why an SOP isn't visible to certain users

Understanding SOP Types

There are two types of SOPs in the system:

Type Description Who Can See It
Company-wide Capstone company-wide SOPs that apply across all properties All authenticated users
Site Specific SOPs created for a specific property Only users assigned to that property (admins see all)

Sidebar Organization

  • Company-wide SOPs appear under a blue dot section labeled "Capstone Company-wide SOP"
  • Site-specific SOPs appear under a gold dot section labeled "Site Specific SOP"
  • Within each section, SOPs are grouped by Category (e.g., Leasing, Operations)
  • Categories are collapsible – click the section title to expand/collapse

Section 3 – Step-by-Step Instructions

Creating a New SOP

1 Log In & Navigate to the SOP Library

Open your browser and go to the SOP Library page. Log in with your admin credentials. You must have admin role to create SOPs.

2 Click "+ Create New SOP"

At the bottom of the left sidebar, click the "+ Create New SOP" button. This opens the creation form modal.

3 Fill Out the SOP Information Section

  • SOP Title (required) – A clear, descriptive name for the procedure
  • SOP Type – Choose Capstone Company-wide or Site Specific
  • Property – Only appears if "Site Specific" is selected; choose the property from the dropdown
  • System – Select from presets or choose "Other" to type a custom name
  • Category – Select from presets or choose "Other" to type a custom name
  • Department – Select from presets or choose "Third-Party Vendor" for custom

Available Preset Options

Systems: Entrata, Gmail, EZOS, Microsoft, Teams, Canva, Instagram, Facebook, TikTok

Categories: Leasing, Operations, Maintenance, Accounting

Departments: Office Staff, Leasing Staff, Maintenance Team, University Partner

4 Add a Training Video or Image (Optional)

Paste a URL into the Training Video or Image field. The system automatically detects the URL type and embeds it appropriately.

  • YouTube – Embeds as an iframe video player
  • Loom – Embeds as an iframe video player
  • Vimeo – Embeds as an iframe video player
  • Google Drive – Embeds as a preview iframe
  • Direct image URL (.jpg, .png, .gif, .webp) – Displays the image inline
  • Direct video URL (.mp4, .webm, .mov) – Embeds a native video player
  • Other URLs – Displayed as a clickable link in an info box

5 Write Section 1 – Purpose

Describe why this SOP exists. This should explain the goal of the procedure in 1–3 sentences.

Example: "This Standard Operating Procedure outlines the process for sending a Renewal Interview Invitation email to residents who have renewed their lease."

6 Write Section 2 – When to Use This Process

Describe the trigger or scenario that requires this procedure to be followed.

Example: "This process should be used after a resident renews their lease and needs to receive the Renewal Interview Invitation email."

7 Add Section 3 – Step-by-Step Instructions

This is the core of the SOP. Click "+ Add Step" to add each step:

  • Step Title – A short name (e.g., "Log into Entrata")
  • Step Description – Detailed explanation of what to do
  • Start lines with • or - in the description for bullet points
  • Steps are automatically numbered with styled step-number circles
  • Click the × button on any step card to remove it
  • Steps appear in the order you add them

8 Write Section 4 – Expected Results (Optional)

Describe what should happen after all steps are completed. This is displayed in a green success info box.

Example: "The resident receives the Renewal Interview Invitation email in their inbox."

9 Write Section 5 – Best Practices (Optional)

List recommendations and tips. Use • or - at the start of each line for bullet points. This is displayed in a blue info box.

Example:

  • Always verify the resident has renewed their lease before sending
  • Use the Responses template instead of typing manually
  • Review the email before sending

10 Click "Save SOP"

Click the "Save SOP" button at the bottom of the modal. The system will:

  • Validate that a title is provided
  • Validate that a property is selected (if site-specific)
  • Auto-generate the HTML content from all form fields
  • Save the SOP to the database with a timestamp
  • Automatically display the new SOP in the content area
  • Update the sidebar navigation

Editing an Existing SOP

1 Navigate to the SOP

Use the sidebar to find and click on the SOP you want to edit. Use the search box or browse by category.

2 Click "Edit" in the Admin Toolbar

As an admin, an admin toolbar appears above the SOP content showing badges and action buttons. Click "Edit".

3 Make Your Changes

The edit modal opens pre-populated with all existing data. Modify any fields as needed.

4 Click "Save SOP"

The HTML content is regenerated from the updated fields. The updatedAt timestamp is automatically refreshed.

Deleting an SOP

1 Navigate to the SOP and Click "Delete"

In the admin toolbar, click the "Delete" button.

2 Confirm Deletion

A confirmation dialog will appear. Click OK to permanently delete the SOP. This cannot be undone.

Sharing an SOP via Deep Link

1 Open the SOP

Navigate to the SOP in the sidebar and click on it.

2 Click "Copy Link"

Click the "Copy Link" button in the toolbar. A shareable URL is copied to your clipboard in the format:

https://yoursite.com/sop_library.html?sop=<sop_id>

3 Share the Link

Send the link to a team member. When they open it and log in, the SOP will automatically display.

Exporting an SOP

Two export options are available from the admin toolbar:

  • Export Word – Downloads a .doc file with a cover page, headers, footers, and full SOP content formatted for Microsoft Word
  • Export PDF – Opens a new browser window with print-optimized styling and automatically triggers the print dialog (choose "Save as PDF")

Section 4 – Expected Result

Expected Outcome

After following this SOP, admins will be able to:

  • Successfully create new company-wide or site-specific SOPs through the form interface
  • Edit and update existing SOPs with the changes reflected immediately
  • Understand why certain SOPs are visible or hidden for different users
  • Share SOPs via deep links and export them to Word/PDF for offline distribution
  • Regular users will be able to view, search, and export SOPs assigned to their properties

Section 5 – Best Practices

Recommendations

  • Use descriptive titles – Include the action and context (e.g., "Sending a Renewal Interview Invitation Email" not just "Email Process")
  • Always select a category – This keeps the sidebar organized and helps users find SOPs quickly
  • Add a training video when possible – Visual walkthroughs dramatically improve understanding. Loom is great for quick screen recordings.
  • Use bullet points in step descriptions – Start lines with • or - for sub-items within a step to improve readability
  • Keep steps granular – Each step should be a single action. If a step has more than 3–4 bullets, consider breaking it into multiple steps.
  • Fill in Expected Results – This helps the reader confirm they completed the procedure correctly
  • Use Best Practices for tips and warnings – Common mistakes, things to verify, and edge cases go here
  • Use Site Specific type only when the process differs by property – If the process is the same across all properties, make it Company-wide
  • Review SOPs periodically – When software updates or processes change, update the affected SOPs to keep information current

Technical Reference – SOP Data Structure

Each SOP in the database contains the following fields:

Field Type Required Description
sopType'company' | 'site'YesDetermines visibility scope
propertyString or nullIf siteProperty name (null for company-wide)
titleStringYesSOP title displayed in navigation
categoryStringNoGroups SOPs in sidebar
departmentStringNoTarget department
systemStringNoSoftware system used
contentString (HTML)AutoAuto-generated HTML from form fields
purposeStringNoSection 1 content
whenToUseStringNoSection 2 content
stepsDataArray of objectsNoSection 3 steps (title + description each)
expectedResultsStringNoSection 4 content
bestPracticesStringNoSection 5 content
trainingUrlStringNoVideo/image URL for training embed
createdAtDateAutoTimestamp when created
updatedAtDateAutoTimestamp when last updated
